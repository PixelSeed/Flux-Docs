    AI Workshop 写操作控制面¶

    本文定义 AI Workshop 场景写操作的唯一授权与执行顺序。模型负责理解需求、 生成具体操作和选择工具；它不生成授权，不管理 Maya Undo，也不根据自然语言 猜测执行是否成功。

    唯一执行顺序¶

    模型工具调用
  -> 稳定 operation ID
  -> WorkshopExecutionAuthorizationService 检查操作权限
  -> 必要时冻结具体工具、参数和 operation ID，等待批准
  -> 批准后直接执行冻结操作（不再通过模型重新生成调用）
  -> 签发绑定具体操作的授权票据
  -> Maya 最终边界校验工具、参数、计划步骤和现场身份
  -> 已有精确回执回放，或占用 operation ID 后执行
  -> Maya Undo 事务
  -> 工具专属写后验证
  -> 持久化结构化回执
  -> 回合状态和最终回复投影

    回执查询先于现场票据校验。成功写入会推进 scene revision，精确回放允许 revision 变化，但仍须验证 host/scene identity；恢复或切换场景后不得套用旧票据。 operation ID、请求指纹和宿主场景身份符合要求时，返回首次执行的持久化结果， 不能再次进入 Maya。相同 operation ID 携带不同参数必须返回 operation_identity_conflict。

    职责边界¶

    • BuildPlanGate 仅服务明确采用注册绑定模块的任务。普通蒙皮、约束、属性、 骨骼创建、临时脚本不要求绑定模块计划，也不自动触发命名、根骨骼或朝向整改。
    • operation_dispatch.dispatch_operation 是模型调用和批准执行共用的派发点。
    • approved_operation 在模型调用前执行消费后的冻结方案；模型只有解释回执的 文本接口。解释服务失败不改变执行状态、不触发再次执行。
    • 描述性模块计划只用于规划与约束，不构成批准对象。变更具体工具或参数必须重新提交。
    • WorkshopExecutionAuthorizationService 是 AI Workshop 写操作的唯一授权决策者。
    • Maya 最终边界不重新推导策略，只验证应用层签发的精确票据和实时场景身份。
    • OperationReceiptService 在副作用前占用 operation ID，并在断线、超时和重放时 防止重复执行。
    • maya_undo_transaction.execute_undo_transaction 统一管理 Undo Chunk 的开启、关闭、 失败回滚和回滚验证。模型不能直接操作 Undo 生命周期。
    • 工具 handler 只实现 Maya 业务动作和领域后置条件，不读取 UI 批准状态。
    • 回合状态只从结构化执行结果投影，最终自然语言不能把失败改写成成功。
    • 路由控制初始工具列表与预算，用户权限控制可调用范围。未加载但已注册的工具 返回加载提示，可通过 tool_search 发现；显式只读和宿主授权检查仍然生效。
    • run_project_file 的批准执行由已有 Broker 登记冻结 PlanRecord 的操作身份， 外层不重复占用同一身份。
    • @selection 在授权与指纹计算前展开为具体节点集合，批准后不按最新选择重新绑定。
    • 未执行的参数错误可被同一命令、同一目标的后续成功回执解除，原始尝试仍留在记录中； 批量调用保留子命令身份。未知结果和实际失败不能据此消除。
    • 已验证写操作的回复投影不再隐式查询 Maya。上下文预取遵守通道配置。
    • 并行读取要求执行器显式声明线程安全的桥接能力；直接进程内 Maya 调用默认串行。

    写工具不变量¶

    所有 ToolDeclaration(effect="write") 必须满足：

    1. AI Workshop 来源没有稳定 operation ID 时，在 handler 前拒绝。
    2. 没有有效授权票据时，在 handler 前拒绝。
    3. 票据绑定工具 ID、参数指纹、operation ID、PlanRecord、AuthorizationGrant、 Maya PID、host session、scene session 和 scene revision。
    4. 写入结果必须具有明确的 execution_state，不能用缺省成功掩盖失败。
    5. 可撤销的场景复合写入必须在一个 Undo 事务中完成，并验证提交或回滚结果。
    6. 相同 operation ID 和参数只能执行一次；后续请求返回持久化回执。

    文件写入、场景 checkpoint 和临时恢复型探测属于不同副作用域。它们仍共享授权、 operation ID 和回执协议，但不能伪装成 Maya Undo 可恢复事务；各自需要对应的原子 替换、版本副本或恢复验证策略。

    第一条端到端验收：创建四个骨骼¶

    create_joint_chain 是本控制面的首个参考实现：

    • 具体命令声明数量、间距、方向和名称前缀；不要求额外绑定模块计划。
    • 应用层签发绑定该调用和当前场景的授权票据。
    • Maya 边界验证票据后才进入 handler。
    • 清空选择、创建四个 joint、检查节点类型、父子链、世界位置并恢复原选择，全部 位于同一个 Undo Chunk。
    • 任一步异常会执行一次整体 Undo，并验证新增节点为零。
    • 成功后相同 operation ID 的重放只返回原回执，不创建第二条链。
    • 用户执行一次 Undo 即删除整条测试链。

    后续场景写能力应复用同一控制面和事务原语，并以本用例的边界测试、失败回滚测试、 重复请求测试和真实 Maya 验收作为最低接入标准。

    小型验收集¶

    scripts/verify_maya_task_acceptance.py 用独立 Maya 2026 mayapy 和临时场景覆盖颜色、 属性、骨骼链、蒙皮、约束、临时脚本和一次批准。默认使用固定模型响应验证执行链； 加 --live-model 使用当前配置的模型，--case skin 可只复测蒙皮。 输出 JSON 记录完成情况、误拦截、操作身份、节点与属性额外修改、耗时和调用次数。

    scripts/verify_scene_exploration.py 验证真实基线、Undo、严重故障恢复、动画和引用 保留、旧身份失效。两者均不连接用户交互 Maya。固定响应、真实 provider 与 UI 验收 必须分别记录，不能用其中一种结果替代另一种。
