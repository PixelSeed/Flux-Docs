    Maya 真实能力与可靠操作（2026-09-17）¶

    目标：模型理解、规划并选择 Maya 操作；已有执行层提供完整目标、现场身份、权限、恢复和可核对的结果。不新增规划 Agent，不强制每次操作前读取整个场景。

    阶段一：现场查询¶

    • query_maya_api 按需读取当前安装版本的命令 flags、节点类型属性、现有节点属性元数据。命令和类型查询不创建临时节点、不执行被查询命令；动态属性必须查询实际节点。命令帮助不完整的 modes/defaults/枚举语义需查版本文档；返回的 URL 是文档入口，不是已联网读取的证据。
    • find_nodes 和 graph_grep 返回 total_count、returned_count、has_more、next_cursor。游标绑定过滤条件、现场/索引版本及成员内容；变更后拒绝继续旧页。索引总数只代表已采集范围，coverage 仍是覆盖率依据。
    • get_editor_state 按需报告 Maya 版本、当前帧、场景、选择数量、读写文件/播放忙碌状态。结果表示采样时状态；它不是独立线程心跳，也不能在 Maya 主线程卡死时即时返回。
    • 完整选择继续走冻结 node_refs 和 @selection；UI 六个名字的预览不参与目标集合。现有 2000 个引用的资源边界继续显式拒绝截断，不静默操作前缀。
    • 现场查询记录宿主、场景、revision、采样时间和帧。读取中场景变化返回 stale，不进入有效事实。安装版本 API 文档不冒充场景存在性证据。

    验证：Python 3.7 的 197 项相关检查通过；scripts/verify_maya_query_contract.py 在独立 Maya 2026 临时场景中 10/10 通过。包含 65 骨骼完整选择、多页读取、改名后旧游标拒绝、真实 skinCluster flags/枚举、证据记录和编辑器状态。未使用用户交互 Maya 或生产场景。

    阶段二：能力边界和验证覆盖¶

    • 原有 ToolDeclaration 增加副作用、恢复方式、验证范围与限制。tool_search、模型循环筛选后的发现结果、写回执和生成文档使用同一个来源。没有标准化验证声明的工具明确标记 unverified，不默认承诺可恢复。
    • capability_contract 只描述支持范围；verification_observed 保留本次实际 verified、检查明细、采样覆盖和 rollback，不把声明范围填成实际已验证证据。
    • 颜色失败后 Undo 必须读回受影响属性，才报告恢复成功；静默 Undo 失败返回 recovery_failed，changed 保持未知。
    • 蒙皮和约束用 UUID 校验真实节点，避免同名不同对象误验收；约束必须连接到指定被驱动对象。蒙皮回执列出顶点总数、采样索引与数量，拒绝负权重/非有限数，不承诺姿态或视觉质量。
    • get_operation_receipt 按需只读查询持久化结果，不需要再次调用 Maya，不将历史执行结果升级为当前场景证据。
    • 能力文档由 python scripts/generate_maya_capability_contracts.py 生成；--check 与测试防止文档/注册声明漂移。参见 生成的操作边界表。

    Python 3.7 的 96 项相关检查通过。独立 Maya 2026 的颜色、蒙皮与约束任务验收通过：真实命令、权限入口、执行回执和会话结果闭环。模型采用确定性测试客户端，不代表真实供应商或交互 UI 验收。

    阶段三：持久化与不确定结果¶

    • 已有 SQLite claim-before-write 机制继续保留。回执为空、损坏 JSON、错误对象结构、身份不符、非有限数或状态矛盾时，返回 unknown；原 operation_id 仍被占用，禁止再次调用写操作。没有明确成功依据的空结果不再默认 completed。
    • 进程中断、保存失败、并发重复请求继续保持不可自动重试。completed + ok:false、completed + verified:false、rolled_back + rollback.verified:false 等矛盾结果不冒充成功。
    • 不确定恢复的 changed 保持 null，经过语义工具包装、持久化与会话链路也不降级为 false。注册操作异常不再声明“未尝试修改”，必须进入恢复检查。
    • 原 Undo 事务与颜色写入共用小型撤销栈所有权检查。每次 chunk 使用独立身份，只有栈顶是本次 chunk 才调用 Undo；空事务失败不会撤销用户上一条命令。Undo 关闭时拒绝启动依赖 Undo 的事务；恢复后仍必须读回验证。
    • 节点 API 元数据局部查询失败显式返回 partial 与错误字段，不伪装为完整元数据。

    Python 3.7 的最终 166 项相关检查通过，覆盖持久化、实际子进程中断、桥接丢失响应、权限、语义操作、场景探索与层依赖；各阶段测试集合有重叠，不相加为独立测试总数。未运行全量回归。

    scripts/verify_maya_recovery_contract.py 在独立 Maya 2026 中 7/7 通过：空事务保护、Undo 禁用、部分写入恢复、颜色回滚读回、静默 Undo 失败、服务重建后不重复创建、历史回执身份。最后还针对脚本批准执行与蒙皮自动执行跑通真实 Maya 会话链路。

    当前边界与手动体验验收¶

    • 现场 revision 与帧可识别已观测到的场景变化，不等于任意第三方插件内部状态的完整哈希。
    • Undo 属于当前 Maya 进程的场景恢复；磁盘文件、进程崩溃后的恢复仍由既有 .maya_ai 基线机制负责。此次没有声称所有工具都能完整回滚，也没有改变用户权限模式。
    • operation_id 防重放覆盖同一请求的重试；不同 ID 的相同自然语言请求不能仅靠文本相似度安全判定为重复。未知结果应核对回执与现场，不能换 ID 盲试。
    • 蒙皮结果只验证声明的结构与权重采样，完整变形质量需要姿态/视觉检查；旧复杂 recipe 未逐项补充的恢复范围明确为 unverified。
    • 新工具是否被真实 Claude/OpenAI 模型及时发现并正确使用，以及 Qt 界面的阅读体验，还需重启 Maya 后交互验收。建议只做三个小任务：查看当前版本 skinCluster 参数、超过 32 个骨骼的完整选择查询、对测试模型蒙皮并询问实际验证范围。不要每轮跑全场景或全量回归。
